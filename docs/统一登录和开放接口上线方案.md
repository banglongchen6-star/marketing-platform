## 第 1 步：上线前检查（约 10 分钟）

1. **服务器 Node 版本**：2026-11-18 经 Actions 查看，服务器已是 Node 20.20.2（npm 仍是 6.14.9，部署日志里的 lockfileVersion 警告来自它，不影响安装），不用升级。
2. **人员重名**：统一登录和开放接口按姓名对应账号。在品宣「系统设置」里看国内、海外两个组织的商务 BD 和品宣主管，同一组织里不能有同名的人（停用的也算）。有就先改名区分，比如「张三（华东）」。
3. **网络**：品宣服务器要能访问 `https://cowork-api.popumusic.cn`（验证身份）；Cowork 要能访问 `https://pinxuan.shiganneibu.com`（绑定时验证密码）。两边都是公网 HTTPS，一般没问题，上线后第 5 步会验证到。

2. Cowork 空间管理员在「空间管理 → 接入系统」点「登记新系统」：

保存后页面会显示一次客户端密钥，马上复制，下一步要用。

3. 在同一页给需要用品宣的同事（或整个部门）开通「品宣工作台」。

## 第 3 步：服务器上写配置文件（经 GitHub Actions，不用登录服务器）

配置写在服务器的 `/root/marketing-platform.env`（代码目录外，600 权限），部署工作流每次启动前读它。密钥不进 GitHub Secrets，也不明文进仓库：

1. 临时分支 `ops/server-setup` 上的工作流已在服务器生成一对密钥，私钥只在服务器 `/root/.pinxuan-seal/`，公钥在分支的 `ops/pinxuan-seal.pub`。
2. 在本机运行该分支的 `ops/seal.sh`，输入第 2 步复制的客户端密钥和新的总管理员密码（输入不显示），生成密文 `ops/secrets.enc`。
3. 提交并推送这个分支，工作流在服务器上解密，写好配置文件；日志里只显示每项「已设置」。
4. 下次部署（推送 main）时生效。

**总管理员密码必须改**：2026-11-18 查看时运行中的进程没有设 `ADMIN_PASS`，线上「总管理员」用的是代码里的默认密码 `admin123`。这一步把它一起设上。`AUTH_TOKEN` 只用来确认同步令牌和它不一样，不用设。

四项 OIDC 没配齐时，统一登录的三个地址返回 404，开放接口返回 503，原来的密码登录不受影响。配置文件写错时部署在启动前停下，旧进程照常运行。

## 第 6 步：验证开放接口

1. 在 Cowork「个人设置 → 账号安全 → 访问密钥」新建一把（可以设成只读）。
2. 用这把密钥查达人库（把密钥放进环境变量，不要贴到聊天里）：


返回里 `organization` 是你的组织、`rows` 有达人和负责人，就通了。没绑定账号会提示去 Cowork 绑定。

## 出问题怎么退

- 统一登录或开放接口有问题：在服务器的 `/root/marketing-platform.env` 里删掉 `OIDC_CLIENT_SECRET` 那一行再部署一次，两者都关闭，密码登录不受影响。
- 代码本身有问题：`git revert` 这两次提交再推送，自动部署回去。
- popumind 那边：在后台停用品宣连接，花小秘的授权自动失效。

## 已知边界

- 账号按姓名对应：品宣里改了名字，Cowork 的绑定就对不上，要在 Cowork 重新绑定。品宣里改密码不会撤销 Cowork 的绑定，要在 Cowork 里解绑。
- 从 Cowork 登录后，这个浏览器的记住登录 Cookie 会变成关浏览器即失效（多个记住的账号共用一个 Cookie）。
- 开放接口的数据范围和系统界面一样：同组织的人都能看到全部数据和金额。以后系统里加了按人限制，开放接口要跟着改。
- 「候选达人」（两轮沟通和结论）没有负责人字段，这次没有开放。
